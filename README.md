# Hollow Reach

Мобильная 2D пиксель-арт survival/base-builder против зомби (Godot 4.x, iOS + Android).
Вдохновение: *Don't Starve* (исследование), *The Walking Dead* (люди опаснее зомби,
моральные дилеммы), *Stardew Valley* (визуальный стиль построек).

> Это начальный скелет проекта: архитектура, autoload-синглтоны, Resource-схемы
> данных и заглушки систем. Графики, сцен-контента и нативных плагинов пока нет.

## Запуск

Открыть папку проекта в **Godot 4.3+**. Главная сцена — `scenes/main.tscn`
(поднимает игровые системы). Ориентация портретная, рендер — `mobile`.

## Структура

```
res://
├── autoload/                 # Глобальные синглтоны (порядок важен)
│   ├── event_bus.gd          #   EventBus — шина событий (грузится первым)
│   ├── game_state.gd         #   GameState — центральное состояние (источник правды)
│   ├── save_system.gd        #   SaveSystem — сейвы с версионированием схемы
│   └── notification_manager.gd #  Push-уведомления (изолированы от game logic)
├── resources/                # Данные через .tres (контент без правки кода)
│   ├── visitor_data.gd       #   VisitorData — визитёры (друг/торговец/враг/дилемма)
│   ├── npc_data.gd           #   NPCData — выжившие + уникальные умения
│   ├── enemy_data.gd         #   EnemyData — типы зомби/мутаций
│   ├── item_data.gd          #   ItemData — предметы/ресурсы
│   ├── balance/              #   GameBalance — все баланс-числа (game_balance.tres)
│   ├── visitor_data/         #   .tres визитёров (примеры: снайпер, заражённый)
│   ├── npc_data/  enemy_data/  item_data/
├── systems/                  # Игровые системы (узлы, общаются через EventBus)
│   ├── noise_system.gd       #   Шум-механика
│   ├── horde_system.gd       #   Блуждающие орды
│   ├── visitor_system.gd     #   Визитёры (+ visitor_generator.gd)
│   └── morale_system.gd      #   Мораль/лояльность группы
├── scripts/ai/               # State Machine для NPC и зомби
│   ├── state_machine.gd
│   └── state.gd
└── scenes/                   # world / base / characters / events / ui + main.tscn
```

## Ключевые архитектурные правила

- **Данные — в Resource (.tres), не в коде.** Новых визитёров/NPC/врагов
  добавляем как ресурсы, без правки скриптов.
- **Связь — только через EventBus.** UI не трогает game logic напрямую:
  шлёт намерения (`*_requested`), слушает факты (прошедшее время сигнала).
- **Баланс-числа — в `GameBalance`**, а не захардкожены в логике.
- **Сейвы версионируются** (`SaveSystem.SAVE_VERSION` + цепочка миграций).
- **Уникальные умения NPC не взаимозаменяемы**: каждое закрывает уникальную
  угрозу, даёт уникальный эффект, или открывает уникальный путь в дилеммах
  (`NPCData.AbilityRole`).
- **Push-уведомления изолированы** в `NotificationManager` — замена плагина
  (FCM/APNs) не задевает остальной код.

## Система визитёров (ключевая фича)

Раз в 1–3 дня к лагерю подходит случайный визитёр. Тип скрыт от игрока; решение
принимается в диалоге с таймером. Враждебные/предатели раскрывают истинную
природу со временем уже внутри периметра (`reveal_chance` / `reveal_delay_days`).
Шанс враждебных растёт с репутацией среди рейдеров (грабёж торговцев → чаще враги).
Все решения логируются в журнал (`GameState.visitor_journal`) для Diary UI.
